# Database Models Documentation

## Overview

This document describes the main database models used by the backend of the 3D asset generation system.

The backend uses SQLAlchemy ORM to define database models and Flask-Migrate/Alembic to manage database migrations.

The main models are:

- `User`
- `PromptRequest`
- `ImportedAsset`
- `GenerationFeedback`

The system also uses two enums:

- `PromptStatus`
- `FeedbackRating`

These models are used to manage users, prompt generation requests, imported 3D assets, prompt refinements, generated files, and feedback analytics.

---

# 1. User Model

## Purpose

The `User` model represents an authenticated user of the application.

Each user can submit prompts, import assets, modify generated results, and submit feedback.

## Table Name

```txt
users
```

## Model Definition

```python
class User(db.Model):
    __tablename__ = "users"
```

## Fields

| Field | Type | Nullable | Constraints | Description |
|---|---|---|---|---|
| `id` | Integer | No | Primary key | Unique identifier of the user |
| `username` | String(80) | No | Unique | Username generated from the email prefix |
| `email` | String(120) | No | Unique | User email address |
| `password_hash` | String(255) | No | None | Hashed password used for authentication |

## Relationships

| Relationship | Target Model | Type | Description |
|---|---|---|---|
| `prompts` | `PromptRequest` | One-to-many | A user can have many prompt requests |

## Relationship Definition

```python
prompts = db.relationship("PromptRequest", backref="user", lazy=True)
```

## Usage in the System

The `User` model is used for:

- signup
- login
- session-based authentication
- linking prompts to a specific user
- restricting prompt history to the authenticated user
- linking imported assets to a specific user
- linking feedback to the user who submitted it

## Example Record

```json
{
  "id": 1,
  "username": "sarra",
  "email": "sarra@example.com",
  "password_hash": "hashed_password_value"
}
```

# 2. PromptStatus Enum

## Purpose

The `PromptStatus` enum defines the possible states of a prompt request during the generation pipeline.

## Enum Values

| Enum Name | Stored Value | Description |
|---|---|---|
| `QUEUED` | `queued` | Prompt has been created and is waiting to be processed |
| `PROCESSING` | `processing` | Prompt is currently being processed |
| `COMPLETED` | `completed` | Generation finished successfully |
| `FAILED` | `failed` | Generation failed |
| `AMBIGUOUS` | `ambiguous` | Prompt is unclear or ambiguous |
| `AWAITING_CLARIFICATION` | `awaiting_clarification` | Prompt requires additional user clarification |
| `INVALID` | `invalid` | Prompt is invalid |

## Usage in the System

`PromptStatus` is used in the `PromptRequest` model to track the state of a generation request.

Example:

```python
status = db.Column(db.Enum(PromptStatus), nullable=False)
```

# 3. PromptRequest Model

## Purpose

The `PromptRequest` model is the central model of the generation system.

It stores a user prompt submitted to the backend and tracks its processing status, generated Blender code, output file, errors, parameters, and version history.

A `PromptRequest` can represent:

- a new 3D generation request
- a modification of an existing generated result
- a refinement of a previous prompt
- a modification request for an imported asset

## Table Name

```txt
prompt_requests
```

## Model Definition

```python
class PromptRequest(db.Model):
    __tablename__ = "prompt_requests"
```

## Fields

| Field | Type | Nullable | Constraints | Description |
|---|---|---|---|---|
| `id` | Integer | No | Primary key | Unique identifier of the prompt request |
| `prompt_text` | String(255) | No | None | Original user prompt |
| `parameters` | JSON | Yes | None | Optional structured generation parameters |
| `generated_code` | Text | Yes | None | Blender Python code generated by the LLM |
| `modification_command` | Text | Yes | None | User instruction for modifying an existing asset |
| `status` | Enum(`PromptStatus`) | No | None | Current processing status |
| `created_at` | DateTime | No | Default: `datetime.utcnow` | Creation timestamp |
| `updated_at` | DateTime | No | Default and update: `datetime.utcnow` | Last update timestamp |
| `result_path` | String(255) | Yes | None | Path to the generated GLB file |
| `error_message` | Text | Yes | None | Error message if processing fails |
| `user_id` | Integer | No | Foreign key to `users.id` | Owner of the prompt |
| `parent_prompt_id` | Integer | Yes | Foreign key to `prompt_requests.id` | Parent prompt used for versioning/refinement |
| `imported_asset_id` | Integer | Yes | Foreign key to `imported_assets.id` | Linked imported asset if the prompt modifies an uploaded file |

## Relationships

| Relationship | Target Model | Type | Description |
|---|---|---|---|
| `user` | `User` | Many-to-one | A prompt belongs to one user |
| `parent_prompt` | `PromptRequest` | Self-referential many-to-one | A prompt can be a refinement of another prompt |
| `refined_versions` | `PromptRequest` | One-to-many | A prompt can have many refined versions |
| `imported_asset` | `ImportedAsset` | Many-to-one | A prompt can be linked to one imported asset |
| `feedbacks` | `GenerationFeedback` | One-to-many | A prompt can receive feedback entries |

## Relationship Definitions

```python
user_id = db.Column(db.Integer, db.ForeignKey("users.id"), nullable=False)
```

```python
parent_prompt_id = db.Column(
    db.Integer,
    db.ForeignKey("prompt_requests.id"),
    nullable=True
)
```

```python
imported_asset_id = db.Column(
    db.Integer,
    db.ForeignKey("imported_assets.id"),
    nullable=True
)
```

```python
imported_asset = db.relationship(
    "ImportedAsset",
    backref="prompt_requests",
    lazy=True
)
```

```python
parent_prompt = db.relationship(
    "PromptRequest",
    remote_side=lambda: [PromptRequest.id],
    foreign_keys=lambda: [PromptRequest.parent_prompt_id],
    backref=db.backref("refined_versions", lazy=True),
    post_update=True
)
```

## Versioning Logic

Prompt refinement is handled through the `parent_prompt_id` field.

When a user modifies an existing generated result, the backend creates a new `PromptRequest` and links it to the original prompt.

Example:

```json
{
  "id": 2,
  "prompt_text": "Create a modern wooden chair",
  "modification_command": "Make it larger and metallic",
  "parent_prompt_id": 1,
  "status": "queued"
}
```

This means prompt `2` is a modified version of prompt `1`.

## Imported Asset Link

When a user modifies an imported asset, the backend creates a new `PromptRequest` linked to the imported file through `imported_asset_id`.

Example:

```json
{
  "id": 5,
  "prompt_text": "Modify imported asset: chair.glb",
  "modification_command": "Change the color to blue",
  "imported_asset_id": 3,
  "status": "queued"
}
```

## Usage in the System

The `PromptRequest` model is used for:

- storing prompt submissions
- storing optional generation parameters
- tracking asynchronous generation status
- storing generated Blender Python code
- storing generated GLB file paths
- storing error messages
- managing prompt version history
- linking modifications to previous prompts
- linking imported asset modification requests
- connecting feedback to generated outputs

## Example Record

```json
{
  "id": 1,
  "prompt_text": "Create a modern wooden chair",
  "parameters": {
    "size": "medium",
    "material": "wood"
  },
  "generated_code": "import bpy...",
  "modification_command": null,
  "status": "completed",
  "created_at": "2026-05-11T10:30:00",
  "updated_at": "2026-05-11T10:31:00",
  "result_path": "static/models/result.glb",
  "error_message": null,
  "user_id": 1,
  "parent_prompt_id": null,
  "imported_asset_id": null
}
```

# 4. ImportedAsset Model

## Purpose

The `ImportedAsset` model stores information about 3D files uploaded by users.

It is used when a user wants to import an existing 3D asset and then modify it through the prompt pipeline.

## Table Name

```txt
imported_assets
```

## Model Definition

```python
class ImportedAsset(db.Model):
    __tablename__ = "imported_assets"
```

## Fields

| Field | Type | Nullable | Constraints | Description |
|---|---|---|---|---|
| `id` | Integer | No | Primary key | Unique identifier of the imported asset |
| `filename` | String(255) | No | None | Internal stored filename, usually with a UUID prefix |
| `original_filename` | String(255) | No | None | Original filename uploaded by the user |
| `file_path` | String(500) | No | None | Relative path to the stored asset file |
| `file_type` | String(20) | No | None | Asset file extension, for example `glb`, `gltf`, or `obj` |
| `uploaded_at` | DateTime | No | Default: `datetime.utcnow` | Upload timestamp |
| `user_id` | Integer | No | Foreign key to `users.id` | Owner of the imported asset |
| `metadata_json` | JSON | Yes | None | Extracted metadata about the imported asset |

## Relationships

| Relationship | Target Model | Type | Description |
|---|---|---|---|
| `user` | `User` | Many-to-one | An imported asset belongs to one user |
| `prompt_requests` | `PromptRequest` | One-to-many | An imported asset can be used by many prompt requests |

## Relationship Definition

```python
user = db.relationship(
    "User",
    backref="imported_assets",
    lazy=True
)
```

The `PromptRequest` model also defines this relationship:

```python
imported_asset = db.relationship(
    "ImportedAsset",
    backref="prompt_requests",
    lazy=True
)
```

## Metadata

The `metadata_json` field stores extracted information about the asset.

The exact content depends on the metadata extraction service, but it can include information such as:

```json
{
  "extension": ".glb",
  "filename": "chair.glb"
}
```

## Usage in the System

The `ImportedAsset` model is used for:

- storing uploaded 3D files
- linking uploaded files to users
- storing file paths
- storing asset metadata
- allowing imported assets to be used as input for modification prompts

## Example Record

```json
{
  "id": 3,
  "filename": "a7f9c2_chair.glb",
  "original_filename": "chair.glb",
  "file_path": "static/models/imported/a7f9c2_chair.glb",
  "file_type": "glb",
  "uploaded_at": "2026-05-11T10:30:00",
  "user_id": 1,
  "metadata_json": {
    "extension": ".glb",
    "filename": "chair.glb"
  }
}
```

# 5. FeedbackRating Enum

## Purpose

The `FeedbackRating` enum defines the possible feedback ratings a user can submit for a generated result.

## Enum Values

| Enum Name | Stored Value | Description |
|---|---|---|
| `POSITIVE` | `positive` | The generated result is considered successful or satisfactory |
| `NEUTRAL` | `neutral` | The generated result is partially satisfactory |
| `NEGATIVE` | `negative` | The generated result is unsatisfactory |

## Usage in the System

`FeedbackRating` is used in the `GenerationFeedback` model.

Example:

```python
rating = db.Column(db.Enum(FeedbackRating), nullable=False)
```

# 6. GenerationFeedback Model

## Purpose

The `GenerationFeedback` model stores user feedback about generated 3D assets.

It is used to evaluate LLM output quality, generation accuracy, and overall success rate.

Each feedback entry is linked to:

- a prompt
- a user
- the generated LLM output
- the generation parameters
- the result file path

## Table Name

```txt
generation_feedback
```

## Model Definition

```python
class GenerationFeedback(db.Model):
    __tablename__ = "generation_feedback"
```

## Fields

| Field | Type | Nullable | Constraints | Description |
|---|---|---|---|---|
| `id` | Integer | No | Primary key | Unique identifier of the feedback entry |
| `prompt_id` | Integer | No | Foreign key to `prompt_requests.id` | Prompt being evaluated |
| `user_id` | Integer | No | Foreign key to `users.id` | User who submitted the feedback |
| `rating` | Enum(`FeedbackRating`) | No | None | Overall feedback rating |
| `accuracy_score` | Integer | Yes | Expected range: 1 to 5 | Score for how well the output matches the prompt |
| `quality_score` | Integer | Yes | Expected range: 1 to 5 | Score for the visual or technical quality of the result |
| `comment` | Text | Yes | None | Optional user comment |
| `llm_output` | Text | Yes | None | Generated Blender code or LLM output |
| `parameters` | JSON | Yes | None | Parameters used during generation |
| `result_path` | String(255) | Yes | None | Path to the generated result file |
| `created_at` | DateTime | No | Default: `datetime.utcnow` | Feedback creation timestamp |

## Relationships

| Relationship | Target Model | Type | Description |
|---|---|---|---|
| `prompt` | `PromptRequest` | Many-to-one | Feedback belongs to one prompt |
| `user` | `User` | Many-to-one | Feedback belongs to one user |

## Relationship Definitions

```python
prompt = db.relationship("PromptRequest", backref="feedbacks", lazy=True)
```

```python
user = db.relationship("User", backref="generation_feedbacks", lazy=True)
```

## Feedback Score Rules

The backend expects:

```txt
accuracy_score: 1 to 5
quality_score: 1 to 5
```

The scores are nullable, but when provided they must be between 1 and 5.

## Success Rate Logic

In the analytics endpoint, a feedback entry is considered successful if at least one of the following conditions is true:

```txt
rating == "positive"
accuracy_score >= 4
quality_score >= 4
```

This logic is used to calculate the success rate in the analytics endpoint and in the CSV export.

## Usage in the System

The `GenerationFeedback` model is used for:

- collecting user feedback
- evaluating prompt generation quality
- storing accuracy and quality scores
- storing comments
- linking feedback to prompts and users
- exporting feedback data to CSV
- calculating success rate and analytics metrics

## Example Record

```json
{
  "id": 1,
  "prompt_id": 10,
  "user_id": 1,
  "rating": "positive",
  "accuracy_score": 5,
  "quality_score": 4,
  "comment": "The result matches the prompt and looks good.",
  "llm_output": "import bpy...",
  "parameters": {
    "size": "medium",
    "material": "wood"
  },
  "result_path": "static/models/result.glb",
  "created_at": "2026-05-11T10:35:00"
}
```

# 9. Main Workflows Using the Models

## 9.1 New Prompt Generation

1. User submits a prompt.
2. Backend creates a `PromptRequest`.
3. `PromptRequest.status` is set to `queued`.
4. Celery processes the prompt.
5. LLM generates Blender Python code.
6. Blender executes the generated script.
7. The output file path is stored in `PromptRequest.result_path`.
8. Status becomes `completed` or `failed`.

Models involved:

```txt
User
PromptRequest
```

---

## 9.2 Prompt Refinement

1. User selects an existing generated prompt.
2. User submits a modification command.
3. Backend creates a new `PromptRequest`.
4. The new prompt keeps the same `prompt_text`.
5. The modification instruction is stored in `modification_command`.
6. The new prompt is linked to the original one through `parent_prompt_id`.
7. The new prompt is processed asynchronously.
8. The version history can be reconstructed using `parent_prompt` and `refined_versions`.

Models involved:

```txt
User
PromptRequest
```

---

## 9.3 Imported Asset Modification

1. User uploads a 3D asset.
2. Backend creates an `ImportedAsset`.
3. Metadata is stored in `metadata_json`.
4. User submits a modification command for that imported asset.
5. Backend creates a new `PromptRequest`.
6. The prompt is linked to the asset using `imported_asset_id`.
7. Celery processes the prompt using the imported file as input.

Models involved:

```txt
User
ImportedAsset
PromptRequest
```

---

## 9.4 Feedback Collection

1. User views a generated result.
2. User submits a feedback rating.
3. Backend creates a `GenerationFeedback`.
4. Feedback is linked to both the user and the prompt.
5. Feedback stores scores, comments, parameters, LLM output and result path.
6. Analytics endpoints use this data to calculate success rate and averages.

Models involved:

```txt
User
PromptRequest
GenerationFeedback
```

# 10. Notes and Implementation Details

- `User.email` and `User.username` are unique.
- Passwords are not stored directly; only `password_hash` is stored.
- `PromptRequest.status` uses the `PromptStatus` enum.
- `GenerationFeedback.rating` uses the `FeedbackRating` enum.
- `PromptRequest.parameters` stores optional generation settings as JSON.
- `PromptRequest.generated_code` stores the LLM-generated Blender Python script.
- `PromptRequest.result_path` stores the relative path to the generated GLB file.
- `PromptRequest.parent_prompt_id` enables version history and iterative refinement.
- `PromptRequest.imported_asset_id` links a prompt to an uploaded 3D asset.
- `ImportedAsset.metadata_json` stores extracted metadata about the uploaded file.
- `GenerationFeedback.parameters` stores the parameters used at generation time.
- `GenerationFeedback.llm_output` stores the generated LLM output for later evaluation.
- `GenerationFeedback.result_path` stores the generated asset path at the time feedback was submitted.
